# 结构化输出改造：第一批实施记录

2026-09-26。本批只推进 A–D 四类，先以较小开发集筛查，再决定是否扩大模型覆盖。

## 已实现

- 新增版本化评分入口 `structured_contract@structured_contract_v1`。Ajv 8.20.0 + ajv-formats 3.0.1，分别支持 draft-07 和 2020-12；引用只使用冻结的本地内容。
- 原始输出必须整体为 JSON。Schema 合规与公开内容要求分别检查，全部通过才得 100，否则得 0；部分分单独保留作诊断，AI Judge 不参与加分。对象键序不影响结果。
- 关闭类型转换、自动填默认值和删除额外字段。未知 Schema 特性、方言冲突、无法解析的引用在调用模型前阻止运行。
- 请求成功但返回空答案记为失败；不自动增加 token 预算重试。基础设施错误单列。逐题指标保存在原有审计字段，界面新增完整成功率，汇总支持按题族平均及独立生成次数统计。
- 创建 12 道开发题、8 道留出题，冻结题面、参考答案、反例、来源文件、来源版本和校验值。留出按 Schema/源任务组分离；仍有共同的 SchemaStore 上游仓库，不宣称跨仓库或跨领域独立。

| 题族 | 本批实现 | 开发 / 留出 |
|---|---|---:|
| A | GitHub Actions 互斥 step 与依赖；留出用 Dependabot 注册中心 | 3 / 2 |
| B | npm 条件导出引用与嵌套；留出用独立编写的递归 AST | 3 / 2 |
| C | null 省略、false/空串保留等显式内容规则；留出含 UTF-8 Base64 | 3 / 2 |
| D | 特殊字符、换行、反斜杠、多层 JSON 字符串序列化 | 3 / 2 |

Schema 来自 SchemaStore 固定版本 `87bc8d9d70f6f5f2792bd01c621e6cb7c217d4a0`，保留 Apache-2.0 许可证。派生步骤去掉编辑器/文档注解，保留标准断言及所需引用闭包。题目和内容规则是本地编写，不能称为官方 SchemaBench 原题。

本批借鉴 SchemaBench 的真实 Schema、Complex/Custom/Escape 与结构加内容联合判定；借鉴 JSONSchemaBench 的方言、来源、正反例和解码方式区分。未实现其完整题集复现。题面档位只表示设计参数，实际难度必须通过模型筛查确认。

## 验证范围与运行方式

只执行与新增功能有关的检查：20 份正确答案全部通过，20 份定向反例全部失败；其中 10 份反例 Schema 合法、内容错误，验证了两者分离。Python jsonschema 4.26.0 对上述 40 份实例独立检查，Schema 结论与 Ajv 一致。它证明的是 Schema 判定一致，不能独立证明全部业务参考答案正确。

10 项新回归检查覆盖复合 const/enum、2020-12 组合、原文解析、JSON Pointer、format、禁止自动修复、无效题预检、空答案计分、重复次数统计和避免无谓人工复核；11 项原有编排审计回归通过。相关 core 构建、server/web 类型检查通过。未执行全项目、容器、全模型回归，也没有因此修改正式题库版本。

可复用入口：

```powershell
# 修改评分器后构建；题包未变不必重新生成
pnpm --filter @zxbench/core build
node scripts/check-structured-contract-pilot.mjs
# 仅题包/Schema 变更时做独立交叉核对
python scripts/check-structured-contract-schema.py
# 默认只跑开发集，每题一次；重复执行跳过所有已有记录
node --env-file=apps/server/.env scripts/run-structured-contract-calibration.mjs --model-id <配置ID> --template-model-id <参数模板配置ID>
```

运行器读取已保存的模型凭据，不把凭据写入结果；核对本地已加载模型身份，冻结采样参数和题包哈希。模型答案、错误原因、token 和时间逐题落盘。出现环境错误即停止继续消耗；中断记录不会悄悄重跑。直接输出轨禁用服务端格式约束，不生成 Judge 请求。

本次筛查使用当前加载的 Nerkyor EfficientThink，沿用 Swift 最近完成运行的生成参数：maxTokens=131072、temperature 未指定、maxReasoningTokens=98000、hardTimeLimitMs=1200000。调用器会按已有约束逻辑收紧实际请求上限。这一宽松预算有助于避免用截断人为制造难度；本批每题只生成一次。

## 晋升条件与后续范围

这些任务目前均为开发候选，不进入正式总分。优先筛查当前高分模型；若开发题仍接近全通过，停止扩大到三模型及留出集，先修改约束交互。每个改版另存版本，保留旧答案，不能拿旧题面的答案给新题面算成绩。

E–H（内容与复杂结构配对、跨格式无损转换、生成 Schema 的边界行为、图形目标渲染）仍待后续实现。正式发布前仍需要独立内容参考复核、实际涉及特性的官方标准测试、不同配置的开发筛查和冻结留出检验。8 道留出每题占 12.5 个百分点，只适合初筛。

## 已完成的最小模型筛查

Nerkyor：12 次单次生成，12 份可评分，0 个环境错误，约 7 分 13 秒。未重跑失败题，未调用 Judge，未运行留出集或另外两模型。

| 指标 | 结果 |
|---|---:|
| 原始 JSON 合法 | 12/12，100% |
| 标准 Schema 合规 | 11/12，91.7% |
| 内容正确及完整成功 | 9/12，75% |

D1、D2 把公开指定的 `test:literal` 键写成 `test`，虽然 Schema 合法，仍未完成任务。D3 额外包了一层 `scripts` 对象，而指定契约要求顶层每个值为字符串，同时仍存在键名及内容问题。三份均以 `stop` 正常结束，失败不是输出截断造成的。

判定：已验证结构合法率可以高于完整任务成功率，但错误集中在一个题族，其中两份属于同一错误模式；A/B/C 仍饱和。不能把 75% 与旧题库 90.2% 直接相减来声称能力下降，也不能据此宣称已消除天花板或形成稳定模型排名。

下一批优先增强 A/B/C 的分支与依赖交互，加入计划中的 E 类简单/复杂输出配对，以区分内容理解和结构负担。暂不消耗现有留出集及全模型矩阵。D 类保留为保真锚点，不能靠增加它的变体数量压低整体分数。

结果保存为 `data/pilots/structured-contract-v1/calibration-development-05c8edd2-6ca6-4c95-9090-e6431b8ab415.json`，包含题面哈希、参数、原始答案和逐项证据。它属于开发筛查，不是正式成绩记录。筛查还发现旧通用“低分自动待人工复核”规则会影响新评分器，已修为明确可判定的契约失败无需人工工单；这不改变本轮分数，也没有为此重跑模型。
