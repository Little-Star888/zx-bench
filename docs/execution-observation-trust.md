给现有返回值协议添加 `throw`、`args`、`same` 等自报字段，不能证明候选程序的真实行为。此次特意构造独立的实验性驱动，未接入正式评分器；不表示以下元数据协议已经在生产中使用。

## 下一步架构验收要求

1. 候选只能影响被测程序数据，不能直接写可信观测通道，也不能退出或篡改可信观测器。
2. 异常从执行引擎结果读取，不能仅依赖候选可改写的异常名称；对象身份由可信层比较对象句柄，不接受自报布尔值。
3. 实参后状态由可信层读取；必须处理访问器、代理、序列化副作用、循环引用及不支持类型，不能静默丢弃语义。
4. 时间、内存、输出限额和容器外层隔离继续有效；宿主不直接运行候选代码，不暴露文件系统、进程或网络能力。
5. 先使本次4类伪造全部被拒绝、正确控制仍通过，再验证具体题目的参考解/原错/变异及旧契约逐点保真。异常类型、别名和状态要求不能删掉以适配新运行时。
6. 新观测协议独立版本化并冻结实现与运行环境；不在 `code_repair@3.5.0` 名下悄悄改语义。JS/TS的验证不自动证明Python或其他语言也安全。

公开文档核对影响了本次架构筛选：Node明确说明 `node:vm` 不是安全机制，因此不能单靠它宣称实现强隔离。[Node官方文档](https://nodejs.org/api/vm.html)

QuickJS的WebAssembly封装提供独立上下文、宿主显式注入接口和运行时限制，可作为JS/TS可信观测原型的候选；这只是依据API能力作出的工程推断，不是安全认证。本轮未安装或选定该依赖，Python方案尚未确定。[QuickJS封装官方仓库](https://github.com/justjake/quickjs-emscripten)

这一阶段需要执行引擎和可信观测层的架构复核，不能以继续批量添加JSON契约代替。按用户约定，在提高思考强度复核之前暂不选择并接入新引擎。
