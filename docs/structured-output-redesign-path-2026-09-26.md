# 结构化输出题库：降低天花板效应的改造路径

2026-09-26。本文保留原设计方案；实施进度见 [第一批实施记录](structured-contract-batch1-2026-09-26.md)。第一批已落地标准评分入口及 A–D 四类小题包，Nerkyor 最小开发筛查为 9/12；错误集中 D 类，其他类仍需加强。正式新题库尚未发布。

**结论：先把完整正确与部分正确分开，再用真实 Schema 的约束组合补充难题，并以独立新样本检验。** 单纯增加字段数量、输出长度、断言数量或提高扣分幅度，都不能证明测量能力提高。任何有限题库仍可能饱和；本方案的目标是对目标模型群维持可解释的区分度，并为后续更新保留稳定锚点。

**从原始基准借用哪些设计。** SchemaBench 与 JSONSchemaBench 是不同研究；它们的历史模型分数不能移植为本地 Qwen3.8 的预期分数。

| 来源 | 核心方法 | 本地采用方式与边界 |
|---|---|---|
| [SchemaBench 论文，§3](https://arxiv.org/html/2502.18878v1#S3) | 真实 Schema；Complex、Custom、Escape；同时检查解析、Schema 与规定字段内容；另测结构约束下的任务正确性 | 建立复杂结构、描述约束、转义保真三类题；用短而可确定的任务测试结构与内容同时正确。其约四万是语料总规模，并非需要全部复制的测试规模。 |
| [JSONSchemaBench 论文，§3–5](https://arxiv.org/html/2501.10868v3) | 不同来源/规模的 Schema；区分引擎接受与实际合规；用正反实例识别过度限制和遗漏限制 | 保存来源、方言、特性与复杂度；对判题器做正反例验证。模型直接输出与约束解码分轨，避免把引擎能力当模型能力。 |
| [StructEval 论文，§2–3](https://arxiv.org/html/2505.20139v1) | 多格式生成与转换；文本解析和视觉渲染采用不同检查 | YAML/XML/CSV/TOML 增加有固定输入的转换保真；Mermaid/HTML/SVG 接入目标渲染器。其部分关键词指标仍可能饱和，不直接照搬为主分。 |
| [JSON Schema 官方测试套件](https://github.com/json-schema-org/JSON-Schema-Test-Suite) | 每个标准版本有 Schema 与已标注合法/非法实例 | 用于验证裁判正确性，不把这些验证器测试冒充模型难题。只执行候选实际涉及的方言和特性，避免无关全量测试。 |

**第一项改造：评分必须能表达“一份答案能否直接使用”。** 当前评分器已产出逐项检查与严格通过标记，前端也显示相关指标；主要维度分仍按多个轴取部分分并可能混入 AI Judge。新版本建议同时提供：原文格式合规率、标准 Schema 合规率、内容保真率、完整任务成功率，以及用于诊断的部分得分。主要成功判定为：所有适用且预先声明的必需检查均通过。标准可确定的结论不用 AI Judge 加分补救。缺少判题能力记为未测量，不算通过。

对纯 Schema 题，任意合法实例都应得完整通过；对附带固定输入或描述规则的题，还需满足这些公开要求。对格式要求为 raw_only 的题，主判定解析完整原文；提取围栏、截取 JSON、补括号等只能提供诊断或单独的修复轨成绩。空白、合法转义的不同写法及对象键序按规范处理，除非题面另有明确、合理的序列化契约。不能给所有 JSON 题暗加键序限制。

新主分按预先固定的题族权重汇总完整任务成功率；同一 Schema 的多个变体先在该家族内汇总，避免一个模板衍生数十题后支配成绩。基础题与挑战题分别展示。部分分用于定位失败层级，历史分数保留为旧版本指标。

**第二项改造：先修裁判对复杂 Schema 的承载能力。** 当前自写 validateJsonSchema 对深度超过 64 或未解析的引用会返回空违规；const 的复合值使用 JavaScript 引用比较。这些行为会同时造成漏判与误判。该实现不能作为大规模复杂 Schema 的唯一裁判。

新挑战轨使用明确方言的标准验证器：建议 Node 端 Ajv 对应方言入口，发布前用 Python jsonschema 对候选参考实例和少量边界反例交叉核对。二者不必在每次模型评测中重复执行。固定版本、格式断言选项、Unicode/数值政策及外部引用快照；禁止强制类型转换、自动填默认值或删除额外字段。未知注解可以合法忽略，但未支持的断言特性必须在准入阶段标记为未支持。参考题自身的引用错误属于题库问题；模型生成 Schema 中的同类错误属于该答案错误。

标准方言不可混用；draft-07 和 2020-12 分入口。format 是否断言必须显式声明，不能默认认为所有实现都会执行。参考：[JSON Schema format 说明](https://json-schema.org/understanding-json-schema/reference/type)、[Ajv 方言入口](https://ajv.js.org/guide/schema-language)。候选涉及的标准测试、已知误判复现、正确替代答案与定向错误答案足以构成首轮裁判门槛。

**第三项改造：用互相影响的约束制造难度，控制无关负担。** 首轮设计八类，每类三档，共 24 道开发样本。档位是设计参数，不预先宣称已验证的难度。优先使用可本地冻结、具有许可证和来源记录的真实 Schema；人工增加的业务/转义要求应标为本地派生，不能声称原样复现官方基准。

| 题族 | 具体变化 | 确定性判定 |
|---|---|---|
| A. 真实配置与组合约束 | 在明确要求的场景下组合 oneOf、if/then、dependentRequired、unevaluatedProperties；要求使用指定功能，避免总选最简单合法分支 | 标准验证器 + 公开的场景要求；每题至少一份合法见证 |
| B. 引用与递归 | 提供可信 Schema，要求生成覆盖指定节点类型和路径的实例；逐档改变有效依赖深度及分支交互 | 引用闭包、必经路径、节点关系；允许任何满足要求的实例 |
| C. description 中的业务格式 | 给出字段规则与固定原值，例如 null 与省略、UTC 格式、Base64 内容或条件出现字段 | 对公开规则执行独立断言；不把 default/examples 自动当成义务 |
| D. 多层转义与保真 | 指定含引号、反斜杠、换行、特殊键名的短原文，嵌入确定路径，逐档增加序列化层级 | 按明确层次解析后逐值比较，接受等价转义形式 |
| E. 内容与结构耦合 | 同一小型确定任务给出简单与复杂两种输出契约；例如同一组记录的条件字段映射 | 原始内容正确率、复杂契约成功率及二者差；不额外引入困难数学 |
| F. 跨格式无损转换 | JSON/YAML/CSV/XML/TOML 使用固定输入，包含前导零字符串、空串、null、特殊字符等明确表示规则 | 按公布的类型映射还原后比较规范化数据；不要默认所有格式表达能力等价 |
| G. 生成 Schema 的边界行为 | 保留现有逆向题，冻结精确业务规则；加入模型没见过的边界合法/非法实例 | 合法样本均接受、非法样本均拒绝；有限样本通过不声称已证明完整语义等价 |
| H. 图与可渲染输出 | 小而精确的状态/关系图或 SVG，固定节点、边、条件与必要可见元素；逐档增加结构交互 | 固定渲染器解析/渲染成功 + 图结构或 DOM/几何断言；截图比较不用逐像素相等 |

可行实例：将 SO-CN-047 的“自行构造多环境配置”改为给定一个固定版本的部署 Schema、环境清单和功能选择，要求在输出中正确激活互斥配置、按选择补齐依赖字段、保留输入字符串并拒绝多余字段。dev/staging/prod 的必需分支写在题面，不通过隐藏要求排除本来合法的简化答案。答案规模保持在十余条记录，难度主要来自结构关系而非长时间抄写。

首轮不依靠巨大输出长度制造失败。50/51 等容量题作为单独压力轨；按实际后端 tokenizer 记录输入/输出预算及截断，避免把不同 tokenizer 或吞吐量当成结构能力。首轮八题族的 E 类配对计入 24 个样本预算内，不另外暗增调用。

**58 道有效题都有对应路径。** 以下为映射建议，题号省略 SO-CN 前缀；每个现有题恰好出现一次。原 052 维持已退役状态。基础覆盖保留固定锚点，不要求所有题都变成难题。

| 现有题号 | 改造路径 |
|---|---|
| 001、002、003、006、029、030、040、047、048 | 从自由造数改为给定真实 Schema、明确场景和小型固定数据的实例生成；对已有混合通过题先保留基线 |
| 004、031、044、053、054、055 | 生成 Schema 与遵循 Schema 分轨；逆向题采用独立边界正反例，正向题提供可信 Schema |
| 005、007、009、011、028、043、049、056 | 转义/字段保真、公开自定义格式规则、边界字符串；028 正则必须实际运行用例 |
| 042、046、050、051、057、058、059 | 控制内容推理负担并设置简单输出对照；容量、排期推理与任意字符限制单列，优先替换纯堆量难度 |

19 道当前全通过题优先抽取改题样本；31 道混合题不一律加难。36 道旧开发题主要是十二种简单转换的三个变体，先作为金标、裁判和基本转换的开发夹具，不自动晋升为困难正式题。

**第四项改造：可复用的校准协议，控制模型调用。** 以下 120 次是首轮开发与筛查预算，不是“已证明彻底解决天花板”的样本量承诺。

| 阶段 | 工作与产物 | 新模型请求 |
|---|---|---:|
| 0，已完成诊断 | 当前 51 题共同答卷的完整检查率、逐题通过分布与失败证据 | 0 |
| 1，裁判与题包 | 标准验证器、成功率字段、来源清单、24 道开发题、16 道独立留出题；正确见证和单缺陷反例 | 0 |
| 2，开发筛查 | 24 个样本 × 3 个模型配置；固定单次生成、统一提示及资源政策 | 72 |
| 3，留出检验 | 16 个新样本 × 同三模型；数据和准入规则在查看答案前冻结 | 48 |
| 可选复核 | 只针对改变结论的异常复跑，另列预算与原因；不把最好的一次替换原记录 | 按需 |

模型选择：一个当前高分本地模型、一个有代表性的较弱本地配置、一个不同模型家族的强参考。若只能取得 Qwen 同源变体，结论范围明确限定为这些配置；这不等于跨家族校准。首轮使用直接输出轨；约束解码只在后续同模型、同样本配对小试中比较，另报支持率、成功率和时间。暂不进行全模型 × 全题库 × 双解码模式的笛卡尔积测试。

按 Schema 来源仓库及归一化结构聚类划分开发与留出，不能只换实体名称、数字或随机种子就宣称独立。第 3 阶段每类两例来自与开发不同的 Schema/源任务组；E 类配对也保持在同一划分内。留出题一旦被用于改规则即成为开发材料，需要新留出实例。对模型发现的错误可以做最小反例修裁判，但必须用未参与修复的源任务验证泛化。

工程故障、模型失败、资源超限分开：有明确基础设施错误的样本单列并补齐配对后比较；请求成功但模型返回空内容、格式不符或触达已公布的输出上限属于未完成任务。不能把所有空输出都默认剔除。每个模型同时报告计划题数、完成数、评分数和排除原因，避免只看成功完成的答案。

候选筛查采用预先登记的工程目标，而非声称来自论文的阈值：挑战部分希望高分模型仍有约 10%–30% 的真实失败空间，全员通过的挑战题占比不超过一半，并且主要题族有可解释的通过/失败交错。基础锚点可以高通过。全员失败先查裁判与歧义；确认超出目标群能力后进入压力轨。若所有模型都很低，减少不相关难度；若仍几乎全对，调整结构组合而非事后压分。不能为了得到预想排名挑题。

16 道留出题每题影响 6.25 个百分点，只适合初步去留。正式稳定排名应按新增独立 Schema/任务组逐批累积证据，报告按源任务组配对重采样的不确定性；近似并列应保留，不用反复生成同一题到产生分差。可以把持续累积到 48–64 个独立源实例作为下一里程碑，达到数量本身也不是统计可靠性的保证。发布后保留锚点与版本隔离；连续新模型在挑战轨接近满分时才触发新批次开发。

**实施顺序及验收物。** 第一个可交付版本包括标准裁判、独立成功率、Schema 来源/特性清单、八题族的小型候选和逐题失败证据；上线前核对正确替代答案以及候选实际使用的标准特性。下一步用 72 次开发调用筛查，再以 48 次留出调用判断是否有继续推广价值。只有通过这些步骤的改题才进入新版本挑战包，原 1.51.2 基线仍可复现；正式成绩不能拿旧题面答案拼装。

新题包至少保存 sourceUrl/sourceRevision/sourceLicense、原始 Schema 哈希、方言、引用快照、题族、公开约束、生成种子、参考见证、裁判版本、预算、split、sourceGroup、父题 ID 和修改说明。模板工具、参考答案生成与验证器实现应有独立性；同一生成函数自证正确不足以准入。

预计实现触点：新增版本化标准验证器和新评分入口；扩展逐题/汇总结果保存标准有效性、完整成功及失败路径；复用现有 criterionResults 展示；新建题包构建、冻结、校准与发布脚本。保留现有有界规则作为历史重放支持。新工作完成之前，不把“评分器更严格”“开发样本通过”或“权威论文里旧模型分数较低”写成已解决天花板效应的证据。

本轮已发布至 1.54.0：退役 12 道饱和旧题，保留 46 道常规题，接入 19 道独立开发题及页面入口，另冻结 15 道未测留出题。按用户最新要求，不再执行原计划中尚未进行的第三配置、留出集或重复验证。原计划的测试预算不是必须花完的任务。完整结果与限制见 [本轮交付](structured-contract-release-2026-09-26.md)。下文保留原设计依据和阶段计划。
