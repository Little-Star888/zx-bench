# 五维度 Docker 执行题迁移与修复收尾（2026-09-26）

## 完成内容

- 审计范围为 194 道原题。189 道仍有效的原题都有 Docker 开发或先导场景，5 道有历史满分饱和证据的基础题退役；有效原题待迁移数为 0。旧题和历史成绩保留。
- 原生执行注册表含 293 个任务包：50 个命令行/脚本包、243 个业务工具世界变体；其中 288 个为 `private_dev` 开发包，5 个为基础回归包。任务包数多于原题数，因为部分原题有相反状态或故障变体。
- 命令行题在隔离容器内实际运行提交脚本并检查输出、文件或 Git 状态。工具和智能体题在容器内运行可重置的模拟状态，按工具反馈、终态和禁止副作用评分；邮件与资金状态均为本地模拟。
- 修复成功调用依赖、对象参数比对、多状态断言、事务失败回滚、提交后响应丢失、受保护文件哈希检查和严格成功评分。`CLI-CN-045-DOCKER` 明确了必须写回并保存脚本的提交规则。
- `TC-CN-032-RECOVERY-1` 现模拟部分邮件投递成功后返回超时，要求重查并只补剩余收件人，全部恰好一次送达后才能通知。状态查询保留完整已发和未发名单，其上下文成本属于题目能力要求。`HA-CN-039-RECOVERY-1` 现模拟扣款落账后丢失响应，要求查询确认，不得换键重复扣款。
- 任务包保存题目、执行器、验证器和参考脚本指纹。相同契约的证据可以复用；题目或环境改变必须重新作答，纯评分改变可在证据充分时离线重评。参考解及核心错误示例用于审查规则边界，不能据此推断模型成绩。

迁移完成时，293/293 个任务包有与当时契约匹配的参考解通过及核心错误示例失败记录。最后改动的邮件分支又单独确认参考动作 100 分、盲目重试 0 分。当前没有进行逐题模型校准；此前两个模型的少量结果只按精确题目哈希与执行/验证指纹使用。完整名单版邮件题有 `deepseek-flash` 的同版 100 分记录，本地 nerkyor 在该精确版本无有效成绩。旧版约 600 秒未完成的结果是固定预算下的性能记录，但不能混作最终版本成绩。
