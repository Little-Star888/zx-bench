## 验收口径

必须分别报告：确定性通过、确定性失败、评分器不可用/语义未验证。词汇匹配、Judge 声称正确、候选自报测试通过都不能升级为可靠语义或行为证据。

首批17个开发对照：8个指令样本、9个PR样本。每个样本含固定ID、答案、目标边界和判定依据，清单有内容哈希。它们是公开开发回归，不是隐藏测试集；不能据此声明模型区分度或防数据污染已经验证。

| 目标 | 首批检查 | 结论 |
| --- | --- | --- |
| 字面指令 | 否定语境中的字面包含、Unicode近形字、两词顺序 | 在此口径内可确定性判分，不能混成语义态度/安全判断 |
| 方案顺序 | 正确顺序、逆序、引用正确示例但实际执行错误方案 | 修复显式“我的实际操作：”选择范围；未声称普遍理解引用、讽刺和立场 |
| PR建议作用域 | 问题字段有“建议”，真正建议字段只有“以后再说” | 修复跨字段偷分；诊断分从100降至85 |
| PR真实语义 | 错误因果、无效长度限制、假参数化、反向修复、结论冲突、注入评分指令 | 旧规则代理仍可给100；语义问题未解决，正式计分已隔离 |
| 容器结果可信度 | 正确断言、错误断言、读取harness后伪造完成标记 | 前两个对照有效，伪造样本也被旧完成标记逻辑判通过，漏洞已复现 |

JSON语法正确、内容包含不可信指令的样本在“仅语法”轴通过是正确边界；不得为了让攻击样本全失败，偷偷扩大该轴为安全语义裁判。

## 已实现的止损措施

- `instruction_checklist_v6` 在存在显式实际操作声明时，按所选实际计划检查步骤，不再由之前被放弃的示例赚取顺序分。保留实际计划正确/错误的配对控制。普通字面包含不受影响。
- `prRuleDiagnosticEvaluator` 仅作离线词汇/证据诊断，不注册成能力评分器。建议存在性仅检查 suggestion 字段。
- 正式 `llm_judge@2.1.0` 返回未测、人工复核和 `SEMANTIC_VERIFIER_UNAVAILABLE`，不调用额外Judge。诊断结果存入独立证据项，不放入正式评分轴。
- 使用现有“评分基础设施不可用”隔离通道：`environmentError=true`、`axisCoverage=0`、`totalScore=0`。这里的0是存储占位，不是模型零分；维度聚合排除它。原因由专用证据前缀区分，不代表Docker故障。真实编排链回归验证Judge不能重新赋分。
- 两道PR题的当前新评测不产生可用能力成绩；正确答案也不会因为隔离得到正式满分。恢复计分必须交付经独立验收的语义核验器，而不是手动关闭保护。
- 版本变为题库1.6.0、指令题scenarioVersion 3.1.0、PR题scenarioVersion 3.1.0。更新冻结哈希，不覆盖历史答案或历史分数。

## 复现命令

```powershell
pnpm audit:adversarial
pnpm gate:adversarial
# 可选：仅在一次性Docker容器中实跑作弊探针，不在宿主执行候选代码
node scripts/audit-deep-adversarial.mjs --containers
```

先构建core后才能运行第三条。常规单测不自动启动Docker。`gate:adversarial` 只验收可靠性修复能否发布：开发对抗样本无开放失败、107道单文件修复题无待迁移项、20道多文件开发题都有隐藏执行测试、两道现行PR题使用自动证据协议时退出0。它不代表新挑战题可以发布分数；挑战题仍需单独完成三档模型区分度筛选。

## 轻量项目的验收边界

- 不要求独立双审或任意仓库通用的PR语义验证器。
- 20道 `project_repair` 保持开发影子题；在正确答案来源未冻结前不得进入正式主分。维护者抽样覆盖JavaScript、Python、Go、C#、Rust和SQL的主要运行风险。
- 新挑战题至少用三个不同模型家族跑相同题目。建议准入阈值为模型分差8分、至少25%的题能分开模型；全员通过的基础题最多占20%，全员失败的题返回修改或实验区。逐题分歧优先于总分排序，避免不同错误互相抵消后误判为“无区分度”。
- 区分度筛选只产生候选清单，不自动确认金标，也不追溯修改历史成绩。

本机容器探针已观察到：`controlsValid=true`，正确断言通过、错误断言失败、伪造候选通过，结果标记 `vulnerability_reproduced`。该结果作为红队发现，不记作通过验收。强防作弊隔离仍未交付。
