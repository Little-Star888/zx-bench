# 轻量发布与题目区分度门槛

ZxBench 的目标是可在个人硬件上维护和复现的轻量评测，不以研究机构级双盲认证为发布前提。正式主分只要求：题面清楚、金标可追溯、评分可复现、环境错误不归罪模型，以及题目对当前模型具有实际区分度。

- 20道多文件 `project_repair` 保持开发影子题；默认全量排除，仅在显式指定题号时运行。
- 维护者风险样本中的 JavaScript、Python、Go 三题已冻结正向答案并完成“原始工作区失败、正向答案全部隐藏测试通过”的容器回放；C#、Rust、SQL 三题仍待补正向金标，不能进入正式主分。

## 区分度准入

同一冻结题集至少在三个不同模型家族上各运行一次，不取多次尝试最高分。默认使用以下轻量筛选值：

- 模型总分跨度至少8分；12题中一题即为8.33分，对轻量筛选已是可见差异；
- 至少25%的题出现模型间通过/失败分歧；逐题分歧优先于总分排序，因为不同模型可能在不同题上失败而抵消总分差；
- 全员通过的基础题最多占正式题集20%；
- 全员失败、含歧义、环境失败或评分异常的题返回修改或实验区；
- 筛选仅生成候选清单，维护者确认后才能冻结，不自动覆盖历史成绩。

三模型同题试跑已经完成。幻觉抵抗三模型得分为100、75、87.5，分差25分、区分题占25%；数学推理得分为75、83.33、91.67，分差16.67分、区分题占25%。两维度均达到轻量门槛。`HC3-002`、`HC3-007`、`MC2-001`、`MC2-002`、`MC2-006` 已以 `challenge_supplement@1.0.0` 接入题库1.30.0，只影响未来运行；它们采用严格二值确定性判分，Judge权重为0。14道全员通过题退出挑战分，`MC2-004` 因三模型均失败而保留实验/重设计。第三模型共20次单次尝试，19题正常完成，`MC2-004` 达到90k上限后截断并按失败保留，未重跑；全程没有Judge调用。
