## 信任边界

1. 宿主评分进程持有标准答案、测试ID、测试清单及比较器，不执行候选代码。
2. 每个测试创建新的Docker容器，只挂载候选源码、固定调用驱动和当前输入。驱动本身不可信；不挂载断言、标准答案、其他测试、数据库或Docker socket。
3. stdout只作为JSON计算结果。宿主逐项比较类型、值、数组长度和对象字段；不相信“PASS”、自报分数、测试数量或完成标记。普通console/print调试日志转到stderr。
4. 超时、非零退出、输出超限，即使打印了匹配结果也不通过。容器独立销毁，测试间不共享可写状态。

这里的“分离”指候选执行容器与宿主oracle/比较器分离，**不是把同一容器内的驱动宣称为可信裁判**。候选仍可篡改自己的运行时或直接打印结果，但必须输出真正匹配该输入的值才得分。此接口不证明其内部调用了哪个函数，不证明内存对象同一性、复杂度、类型检查或副作用正确。

## 容器与失败归因

- 非root、无网络、只读源码挂载、只读根文件系统、32MiB临时目录（noexec/nosuid/nodev）、cap-drop、no-new-privileges。
- 单容器128MiB、1CPU、32PID；stdout+stderr合计64KiB，按字节限额。测试工作预算3秒，外层Docker CLI另留5秒启动/传输余量；不是候选拥有8秒的精确CPU预算。
- 只用本地缓存的 `node:20-alpine` / `python:3.12-alpine`；不隐式拉镜像或安装依赖。镜像digest固定与跨环境复核尚待后续验收，不能假定tag跨机器恒定。
- Docker daemon探针、镜像检查与容器State来自宿主控制面。候选自己打印“Docker unavailable”或exit(125)不会自动获得缺测豁免。
- 超时后按本次UUID容器名执行清理，不影响其他容器；临时目录异步清理，避免阻塞服务。

Docker不是形式化安全证明，也未完成内核逃逸、微架构侧信道等独立安全审计。不要把本阶段称为“任意恶意代码安全认证”。
