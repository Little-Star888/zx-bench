# 执行任务包与题库维护

本轮落地采用 zxbench 原生任务包。尚未声称 Harbor 格式兼容，也未把开发题提升为正式成绩。

## 任务与证据

`data/execution/registry.json` 登记 293 个执行任务包：50 个 CLI/脚本包、243 个业务恢复/授权变体，共 288 个开发包、5 个原有基础回归包。不新增简单基础题。
每个包包含题面、固定镜像与预算、完整场景、参考脚本和核心错误反例。
CLI 包运行 `node scripts/check-execution-task-pack.mjs --task=题目ID`；业务包运行 `node scripts/check-recovery-world-docker.mjs --task=题目ID`。两者都在隔离 Docker 中检查新题的参考动作与核心错误反例。
报告记录环境/评分指纹及脚本指纹。完全相同的已通过报告自动复用，`--force` 才强制重新验证。
可先加 `--plan-only` 查看哪些证据可复用；该模式不启动容器、不调用模型。
判分文件和参考脚本只由控制端读取；候选会话只获得输入文件和候选脚本。

目前是原生包，执行依赖 zxbench 运行器；不是独立分发的 Harbor 任务。
部分开发输入仍只覆盖原题的代表性规模与边界；一般文档转换、渲染或外部业务服务不得据单一样例宣称通用能力。业务状态题使用本地合成状态，不触达外部系统。
参考解通过与错误解失败只证明局部判分有效，不能证明已经没有漏洞或题目有区分度。

## 复用规则

- 题面、输入、初始化、工具实现、镜像、预算变化：重新作答。
- 仅独立断言或评分实现变化：已有充分证据时离线重评；脚本题仍可能需要在 Docker 重执行原脚本，但不重新调用模型。
- 仅元数据变化：复用成绩。
- 缺少旧执行指纹、证据或旧记录存在环境故障：不能自动认定可复用。

校准脚本已保存执行与判分指纹，`--replay-changed` 会拒绝环境已变化的轨迹。
校准可用 `--only` 限定必要任务；基础回归题需显式纳入。旧校准脚本的默认选择可能只是迁移早期的子集，不代表全部 293 个执行包。
输出与已有 16 题校准分别保存；模型仍使用用户指定的两个。
复用判断还受原脚本的模型配置哈希约束，不能跨模型或参数配置复用。
判分器与执行器指纹使用实际加载的编译后代码。构建变更后的核心包才能运行新版规则。

## 本轮题目退役

`CLI-CN-049/051/053/052`、`TC-CN-028` 各自的七个历史完整运行均为同题哈希、同场景版本、同评分版本且满分。
这五道基础题已从正式选择中退役；数据库与 JSON 定义同步，历史结果保留。前三道原题已有 Docker 回归包，后两道不再新造基础执行题。
这是旧版基础题评分饱和的维护决策，不代表七个独立模型家族或新执行版已普遍饱和。
证据、运行 ID、旧哈希与备份位置见 `data/execution/retirement-evidence.json` 和 `data/execution/retirement-evidence-batch2.json`。

现有 16 题双模型校准由 `node scripts/screen-execution-calibration.mjs` 读取原记录筛查。运行器已更新，旧记录缺少执行指纹或哈希不匹配时标记需要匹配证据；原统计只作历史结果，不能冒充当前规则的校准。
双方一次满分只标记候选；不得直接删除。复杂题旧版的文本评分满分也不能证明执行能力饱和。
主榜准入需要检查关键断言、合法替代解、保护状态以及结果分支；严格成功必须所有关键条件通过。
部分得分仅用于定位失败；成本只在成功任务之间比较。用户指定的两个模型用于开发校准，
不把这两次样本推断为对所有模型的统计结论。

## 验证与下一步

本轮未重复完整 CI 或模型评测。293/293 个注册包的参考解通过、核心错误示例失败，且报告指纹与最终任务契约一致；失配报告重做，其余复用。题库版本为 1.56.0，总体有效题 831，五维度审计范围内有效原题 189；题库、数据库定义状态和哈希一致。

既有双模型 16 题筛查结果只属于旧版本，不能推断新迁移任务的难度。接下来需要检查合法替代路径、环境真实性和模型区分度，再作正式题库切换决定。任务包数量不等于正式可发布题数。
