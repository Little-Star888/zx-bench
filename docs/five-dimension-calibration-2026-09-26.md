深度命令行的七模型平均分范围为 89.69–96.82；13 道全满分题为 `CLI-CN-003/019/027/029/030/031/032/033/035/049/051/052/053`。其中调查题 `CLI-CN-031/032/033/035` 特别值得优先检查旧评分是否奖励了答案文本，而没有检验模型自行探查与真实终态。工具工作流虽有四道全满分题，但整体逐题分歧较多，不能概括为整个维度都已失去区分度。智能体、安全和闭环的旧运行版本不齐，不能据此定量判断天花板。

## 新 Docker 开发样题

当前 15 个源题对应 16 个开发场景：CLI 脚本 1、工具世界 4、零售闭环 5、自主调查 6。逐题静态检查显示：16/16 合同验证通过，16/16 题目哈希一致，16/16 本地镜像 ID 与冻结值一致。CLI 脚本有两组输入案例。所有 16 道仍为 `private_dev` 且 `reviewStatus=unreviewed`，因此目前只证明配置和环境锁定，不证明难度或评分区分度。

本轮按用户确定的两模型口径校准同一冻结 Docker 题集，逐题审核环境错误、可替代正确路径、双方通过和双方失败，再使用轻量区分度门槛。两模型对照不能单凭总分判定题目有效。其余 179 个源题还没有 Docker fixture 与独立 gold，也不应改为执行评分或发布新榜单。

## 本轮行动结论

先保留 16 道开发样题并完善正反参考轨迹；优先处理旧 CLI 全满分且涉及自主调查的题，以及旧工具工作流全满分题。按两模型逐题分歧和轨迹审查筛选执行题。此轮不重跑已有的 806 题正式评测，也不根据旧分数重排历史成绩。

## 两模型最终校准状态

`TC-CN-054` 的容器工具现接收 `{old,new}` 结构化补丁，只在目标文件仍等于 `old` 时应用 `new`。错误补丁被拒绝、正确补丁更新文件的容器检查通过。两模型在修订后的题上各重新作答一次，均为 100 分。nerkyor 首次重跑因 Docker 工具会话固定 120 秒而报环境错误；会话寿命现跟随题目预算，补跑完成为 100 分。该错误保留在 `previousAttempts`，不计模型零分。

当前冻结的 **16 对同题结果全部完成、哈希一致、环境错误 0**。nerkyor 有 15 道满分、`HA-CN-045-EXEC-PILOT` 80 分；deepseek-flash 有 15 道满分、`CLI-CN-033-SHELL-PILOT` 67 分。双方同时满分 **14/16（87.5%）**，仅这两道题具有经轨迹核实的分差：nerkyor 在记忆题先调用了未提供的工具；deepseek-flash 在调查题读到了正确的 TOML 启动配置，却回答了 YAML 中的端口。零售闭环 5/5、CLI 脚本 1/1、其余多数工具与命令行调查题仍同时满分。

本轮只使用用户指定的两个模型。Bonsai 本地服务未启动；GLM 远程接口返回资源余额不足，未产生有效作答；随后第三家族尝试按用户要求终止。这些都不进入两模型统计。**结论：执行环境与确定性评分可用，题目难度仍不足以发布为有区分度的新榜单。** 继续迁移时，应先构造结果分支和故障反馈，而不是只增加提示长度或轮数。

最终验证：本轮代码的完整本地测试 1789 通过、213 跳过，整仓构建通过；结构化补丁正反路径和两模型逐题 Docker 运行均已实际检查。未重复运行先前已通过且未受改动影响的整套容器套件。
