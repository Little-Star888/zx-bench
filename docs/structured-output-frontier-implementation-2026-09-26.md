# 结构化输出前沿改造：实施与筛查记录

日期：2026-09-26。状态：**裁判和开发题已落地；新题尚未达到可发布的难度证据。**

## 已实施

- 新增 `structured_contract_v4`，沿用原文格式与 JSON Schema 验证，增加服务器端私有金标、逐叶路径召回、类型、值、证据 ID 和额外字段诊断。整题必须全部通过才得 100；缺裁判环境记未测。旧 v1–v3 的分数含义不变。
- `/api/scenarios` 对 v4 题不返回内联金标字段；题面只保存 oracle 引用和摘要。开发题的金标放在 `data/pilots/structured-contract-frontier-v*/oracle.private.json`，不进入网页静态资源。
- 页面增加 v4 逐叶值准确率及路径覆盖率显示。历史标准契约完整通过率仍保留。
- 制作 v1.1 开发题 8 道、来源 ID 不重叠的留出题 4 道；另做 v2 共享额度顺序账本、v3 43 条打乱档案的多跳检索单题探针。所有新题仍是开发候选，没有加入正式题库。
- 引入 [SOB 官方文本基准](https://huggingface.co/datasets/interfaze-ai/sob)的固定 8+4 题开发包（v4），包含原文、问题、Schema、金标、原始记录 ID 和许可说明。其来源为 HotpotQA，遵守 CC BY-SA 4.0；题目仍处开发状态。

## 最小验证与结果

必要的本地准入：v1.1 的 12 份金标与四类各一份定向错误、v2/v3 各一份金标与定向错误，均按预期判分；core 构建、server/web 类型检查通过。未跑全量测试。

模型只筛查本地 Nerkyor，沿用保存的生成配置、每题一次直接生成、无 Judge。v1–v3 共 **7 次实际模型调用**：v1 首轮四题（D 的证据规则有歧义，原答卷保留并判为无效难度信号）；修订 D 后只重跑该题，其余三题复用原答卷；v2、v3 各一次。最终有效开发探针为 **6/6 整题通过**：v1.1 四题、v2 一题、v3 一题。v2 的 96 个目标叶值、v3 的 41 个目标叶值也全部正确。没有对第二模型或留出题调用，因为较弱本地模型已在每个已筛查设计上满分，再测同模板不能支持“克服天花板”的主张。

正式结构化输出题保持 **60 道**，SOC4 发布数为 **0**。不退役旧题，不把开发题成绩并入正式成绩。

## 官方来源的评分歧义审计

公开 SOB 逐题记录可用作**零新增模型调用**的候选筛查，但不能直接把低精确匹配率当真实难度。在下载的前 100 条文本题中，四种公开模型的逐题分数显示一些“难题”；审阅两个模型的原始答案后，常见扣分是等价描述：`T. S. Eliot` 与 `T.S. Eliot`、`San Jose, California` 与带国家后缀的金标、`car rental` 与 `car rental company`。有的 Schema 明写“城市和州”，金标却额外包含国家。直接套用整字符串相等会制造虚假的非满分。

SOB 另有 **3 次本地模型调用**。Nerkyor 对 SOB-055 的首次答案为 5/6 个叶值正确，唯一差异 `car rental` 是有效等价说法；v4 oracle 已版本化接受这一写法，保存原答卷重新判为 6/6。SOB-009 为 12/12。SOB-028 为 4/5，差异只在地名是否附加 `United States`，且 Schema 描述要求“城市和州”；这也不能计作真实能力失误。**目前未观察到已排除裁判歧义的有效难度信号。** SOB 候选全部标为 `unreviewed`；公开逐题模型成绩的筛题结果、原始差异及许可来源保存在 `data/pilots/sob-source/`，不得未经复核直接发布。

## 失败原因与下一轮的设计门槛

当前 v1–v3 虽增加来源数、依赖跳数、条件分支和行数，来源仍是干净的本地合成记录，规则也在题面完整写出。本地模型能稳定执行这些清晰的算法。结果证明**复杂度指标本身不能代替实测难度**。v1 留出按来源分开，但题族规则模板仍共享；v2/v3 无留出。当前 Schema 是本地编写的标准 JSON Schema，不是从真实业务 Schema 提取，不能宣称完成 SchemaBench 式真实 Schema 采样。

下一轮从 SOB 等真实来源中先剔除**自由描述不能唯一判定**的字段，或在题面约束规范写法并人工冻结等价值集合。优先寻找数值、枚举、实体关系、集合完整性等可客观判定的错误；按文档来源、规则模板和实体组隔离留出。每题族先用已有公开逐题记录和人工审查筛候选，再只用本地模型测一题。若继续全对，停止扩写同族题；若出现可解释的内容错误，补做同源简单输出对照和独立留出，再决定是否一对一替换饱和正式题。第二模型只用于通过首轮筛选的题族。发布前仍须保证正式题约 60 道和历史分数版本隔离。

这不是降低评分阈值：未来题目须保留合法替代答案，等价证据需在 oracle 中预先列明。观察到的非满分必须来自可复核的来源理解或格式规划错误，而非歧义、长文截断、运行环境、输入法或裁判漏洞。

## 2026-09-26 追加：从公开答卷反推的可执行解法

先做了零本地模型调用的审计：下载 SOB 官方前 500 道文本题及 Qwen3.5、Gemini3.1 的公开原始答卷。`scripts/audit-sob-objective-candidates.mjs` 只筛数值和布尔叶值，得到 4 道有公开错答的题。人工逐题审阅结果冻结在 `data/pilots/sob-source/objective-review.json`：153 的人物字段位置没有定义，374 的专辑列表范围和顺序没有定义，399 的 Dick Harris 是重名人物，均拒收。414 的两个影片拍摄时间有明确先后关系，是唯一可用的事实错答候选。这一结果否定了“从现成 hard 标签批量取题即可解决天花板”的路径。

**题库的真实目标应拆成两种可报告能力。** 第一种是格式遵循：语法、Schema、必需字段、类型、枚举、额外字段。第二种是有依据的内容填写：数值、日期、布尔、唯一实体、完全集合及证据。两种能力单独报告，整题通过仍保留。自由描述字符串若没有唯一规范答案，不作为硬失败依据；若需要该字段，则题面明确允许的格式和等价值，或改为客观枚举/引用原文片段。数组必须指定排序规则，或者按集合判分。题面必须说明所有目标字段的取值范围，重名实体必须在题面消歧。

**防止把普通阅读理解错答当成结构化输出难度。** 每个开发候选先制作一个等内容的简表答案对照（同一来源、同一必答事实，输出为编号答案），与结构化 JSON 版本成对。只在“简表事实正确、JSON 事实或格式错误”时记为结构化特异失误；两边都错归入来源推理难度，不作为格式区分度证据。额外报告内容条件准确率，即在格式通过的答案上核对客观事实。公开模型的原始错答只用于挑题，不能替代这个成对验证。

**准入与扩库顺序。** 先从真实来源准备少量客观题，复核来源证据、唯一金标、排序/别名规则，按来源和题型分组。每类仅测一组成对探针；若本地模型在结构化版本仍满分，停止扩写该类。出现真实的结构化特异失误后才做第二模型和来源隔离的留出题。至少有两个不同来源组和两个不同题型出现此类失误，且留出题复现，才允许按一题进一题出的方式替换旧饱和题；正式题数始终保持约 60，历史分数保留版本边界。发布后的难度以留出题的实际分布为准，不以题长、Schema 深度或官方 hard 标签推断。

当前审计只提供一条干净的公开事实错答线索，**尚无结构化特异失误证据**。因此不把 414 或其变体直接算作新难题，也不再对有歧义的 SOB 候选做本地调用。下一轮优先扩展真实来源中客观、可唯一判定的题型；若仍找不到结构化特异失误，需要承认当前模型在现有格式契约上的能力已接近上限，并转向真实业务 Schema、跨字段约束、增量修复与拒答边界等新的能力面，而不是人为加严字面匹配。
