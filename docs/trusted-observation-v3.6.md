## 为什么增加独立观测器

前一阶段的12次负例实验表明：让候选程序所在解释器输出 `throw`、`same`、`args`，即使标准答案在宿主，也仍然可以伪造元数据。详见[原始负例记录](execution-observation-trust.md)。新的 JS/TS 通道不再赋予候选进程观测报告的写权限。

外层为无网络、非root、只读根目录的容器；容器中的可信 Node 程序加载 QuickJS/WASM。候选只在 WASM 的候选上下文执行；另一个不向候选暴露的服务上下文负责读取数据属性。宿主保留测试ID、预期答案和比较逻辑，挂载内容只有当前调用、候选源码、可信驱动与3个固定依赖目录。没有挂载整个项目或题库。

QuickJS 封装提供独立上下文、显式宿主接口和资源限制，但这些 API 本身不是完整安全认证；本项目据此构造并实测了受限接口。[官方仓库](https://github.com/justjake/quickjs-emscripten)

| 要验证的行为 | 可信观测方式 | 不接受的替代证据 |
| --- | --- | --- |
| 抛出异常 | 引擎调用错误结果、保留的原始 Error 原型、无标签伪装的 Error 品牌 | stdout、可写的 error.name、普通对象冒充错误 |
| 实参调用后状态 | 私有服务读取数据属性，与宿主预期比较 | 候选 JSON.stringify、toJSON、调用前副本 |
| 返回对象身份 | 返回句柄与保留的原始实参句柄做引擎严格相等比较 | 候选自报 same=true、值相等的新对象 |
| 返回值 | 有限、无副作用的 JSON 数据树，与宿主预期比较 | “已通过”字符串、通过计数、访问器计算的报告 |

输入在候选上下文创建，避免把可信服务对象及其构造器链交给候选。对象读取拒绝访问器、符号、自定义原型、稀疏数组、循环、非有限数和负零；不会调用候选序列化函数。ASCII JSON 桥保留 NUL、Unicode 与孤立代理项。Proxy 不启用，模块导入固定拒绝，未开放宿主文件、进程、网络和对象。实现对引擎句柄及调用结果的使用依据上游接口，并通过专门攻击验证；不是用同进程 Node eval/vm 执行候选。[上游上下文实现](https://github.com/justjake/quickjs-emscripten/blob/main/packages/quickjs-emscripten-core/src/context.ts)

### 明确的限制

- 限同步调用、JSON数据类型。Promise 为模块初始化所需而启用，但不执行待处理任务；拒绝返回Promise、模块异步结果和待执行任务。不声称识别所有被丢弃且没有待处理任务的Promise。
- 错误类型是“原生 Error 品牌 + 当前原型”的结构契约，不证明历史上调用过哪个构造器。引擎 InternalError/资源耗尽不能赚取预期抛错分。
- 实参比较认证选定JSON数据属性，不认证完整描述符、所有别名关系、内部调用次数或完整堆历史。getter/Proxy等超出契约的返回结果拒绝，不静默转换。
- TypeScript转译后执行，另有不执行源码的 Node 模块语法检查；不是类型系统专项，也不承诺完整 Node API/语言环境兼容性。
- JS/TS的实测不自动推广到Python。Python对象身份、异常和输入状态可信观测仍未交付；不继续信任候选可改写的Python驱动报告。

四道迁移题均在题面公开受限环境、数据类型和资源预算，不能让模型提交后才发现没有完整Node能力。可信观测器在加载候选前的初始化/自检失败归为环境缺测；候选调用阶段的拒绝不会仅凭同样的错误文字冒充基础设施问题。

运行时固定 `quickjs-emscripten-core@0.32.0`、`@jitl/quickjs-wasmfile-release-sync@0.32.0` 及对应FFI依赖，锁文件与源码哈希进入执行冻结清单。Node镜像固定为 `node@sha256:fb4cd12c85ee03686f6af5362a0b0d56d50c58a04632e6c0fb8363f609372293`，只用本地缓存、不自动拉取。WASM内存32MB、栈64KB、默认执行预算1秒；外层容器192MB/1CPU/32PID及硬超时，输出64KiB。资源拒绝是边界，不代表算法性能结论。

## 四题迁移：旧断言保留，挑战单列

| 题目 | 参考解：旧点 / 开发点 | 原错：旧点 / 开发点 | 新验证重点 |

| CP-L1-JS-002 chunk | 5/5、2/2 | 0/5、0/2 | 分组、尾组、指定RangeError |
| CP-L2-TD-JS-001 parseRange | 4/4、3/3 | 0/4、0/3 | 闭区间、逆序拒绝、格式边界 |

| CP-L3-AW-JS-005 trimHistory | 2/2、3/3 | 0/2、0/3 | 按旧断言检查保留system与最新消息，不暗加完整数组断言 |

4个参考解、4个原始错误实现和12个语义变异在旧断言与新正式评分入口逐点对账，共69组判定配对一致（前3题59组，trimHistory另10组）。旧执行器只在一次性容器运行这些固定控制，不恢复生产评分权。deepMerge的对象键顺序按数据语义比较，不保留无意的JSON字符串键顺序限制；这是版本化边界修正，不是所有未知实现等价的证明。

开发挑战暴露了旧题的实际缺口，例如仅拒绝零而不拒绝负分组长度、修改deepMerge第二个输入、空合并时复用输入对象，以及trimHistory错误保护index 0、预算恰好相等时过度删减。没有把新增断言悄悄塞入旧题或重新计算历史得分。这些参考实现及11个挑战都是开发控制，**未取得独立人工金标审核**。trimHistory原来只读length/role/text，并未断言Array或全部字段；新契约保留这个弱断言边界，由比较器回归记录，不能借迁移悄悄收紧。

新观测专项分两批实跑89组：首批84组（67个观测正反/边界样本、15个题目控制组、2个额外异常/资源组），再跑trimHistory的5个控制组，均通过。67个样本包括18个正常正例、47个应拒绝攻击和2个明确记录的可接受边界；“通过”指行为符合预期，不是67个攻击都被拒绝。覆盖伪造报告、原型污染、序列化副作用、服务上下文泄漏、导入、异步、身份、Unicode与资源攻击。

## 新版 PR 可执行证据题

`PR-WITNESS-SQL-001@1.0.0`，协议 `pr-witness-sql-v1`。题面与实现的开发冻结见 [pr-witness-development.json](../data/scenarios/pr-witness-development.json)。该题尚未注册为正式评分器，不增加595道当前正式题目数，也不代替旧PR题的人工评审。

题目源自 PR-ELITE-012 的真实 SQL 插值新增行；版本化新题显式使用独立 SQLite 环境与表结构，不假装重建原应用或原项目数据库。候选提交严格JSON：一个能重放的注入输入，以及只读SQL模板和单个name参数绑定配置。输入不当、伪参数化或任意Python/TS源码不进入可信驱动执行。

执行链检查：原查询在两组数据库数据上确实返回数据库中真实存在的越权记录；参考查询在同一输入恢复精确匹配；候选修复在两个世界的完整回归以及新增合法名称上保持正确记录、类型、字段与重复行语义。第二组改变ID/role，添加随机新login、空login与2048字符边界；每个世界从实际表数据补齐全部合法名回归，宿主保存seed、完整数据与哈希以便重放。完整正确方案产生33条SQL执行证据，其中29条是候选修复检查。伪造UNION记录、复制公开表中的某行、硬编码旧ID/角色、拒绝全部请求或长度截断合法名称均有反例控制。有限开发回归不是对所有SQL输入的形式证明，也不是秘密独立测试集。

候选SQL仅交给固定可信Python驱动的SQLite接口，没有Python源码插值、eval/exec、候选上报通过通道或文件/网络权限。数据库只读；authorizer禁止写入、PRAGMA、ATTACH、schema读取和扩展加载，限制函数、SQL长度、返回行数和VM步数。镜像固定为 `python@sha256:d09d15e60962ca365d1cd544a48773bac9d33f2fb1b00f2aa0deec78ade7dc31`，验证SQLite 3.53.2。它不测自然语言因果解释、严重等级、支付、JWT、日志或架构评审，不能以该题通过推导完整PR能力。
